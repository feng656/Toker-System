# 业务规则与状态口径说明

> 项目：自由光·拓客系统（一期）
> 责任域：产品 / 运营 / 前端与验收
> 依据：《奇迹于你和浆果的分工.docx》第 4.1、4.2、8.1 节 + 现有代码（`app/models.py`、`app/api.py`、`app/generator.py`、`app/quality.py`、`app/classifier.py`）
> 版本：v1.0　编制日期：2026-11-02

本说明是**页面与接口共用的唯一口径来源**。前端按本文档渲染状态标签、按钮与提示；后端字段含义与本文档冲突时，先改本文档再改代码（见《分工》8.2：后端不把展示文本当作业务状态，前端不自行推断后端状态）。

| 管理员 admin | `admin` / `admin123` | 全部 | 平台凭据、合规红线、用户管理、素材/选题/内容/线索全部写操作、删除素材 |
| 运营 operator | `yunying` / `tk123456` | 工作台、今日待办、内容管理、素材库、选题池、线索看板、数据看板、设置、帮助 | 素材/选题/内容/线索写操作；**无**删除素材、**无**凭据/红线/用户管理 |

## 二、关键业务对象与字段口径

| 对象 | 表 | 关键字段 | 业务含义 |
| --- | --- | --- | --- |
| 素材 | `materials` | `category` 分类 / `biz_line` 业务线 / `publicity` 公开级别 / `tags` / `enabled` | 内容生成的唯一事实来源；`enabled=false` 的素材不进入生成上下文 |
| 选题 | `topics` | `biz_line` / `theme` 主题 / `title` / `angle` 角度 / `score` 表现分 / `status` | 内容的源头；`status=active` 才参与每日生成 |
| 内容 | `contents` | `title` / `status` / `source` / `review_note` / `scheduled_date` / `topic_id` | 一个选题的一次生成结果（内容包），下挂多个平台变体 |
| 内容变体 | `content_variants` | `platform` / `body` / `cover_text` / `hashtags` / `compliance_ok` / `quality_score` / `confirm_status` / `publish_status` / `published_url` | 一条内容在各平台的落地稿；**发布量与已发布状态以本对象为准** |
| 指标 | `metrics` | `variant_id` + `stat_date`（唯一）/ `views` `likes` `comments` `collects` `shares` `new_fans` `dm_inquiries` | 人工确认后录入的平台效果数据；同版本同天重复录入 = 覆盖更新，不累加 |
| 互动 | `interactions` | `platform` / `kind`(comment/dm) / `author_name` / `body` | 评论与私信原文，AI 打标的输入 |
| 线索 | `leads` | `intent` / `identity` / `need_summary` / `contact_info` / `brand_need` / `reply_suggestion` / `assignee` / `status` / `follow_notes` | 互动打标后的销售跟进对象；一条互动可生成一条线索 |
| 合规规则 | `compliance_rules` | `rule_type`(forbidden/ad_law/required) / `pattern` / `enabled` | 内容生成前的硬校验词库 |
| 平台账号 | `platform_accounts` | `platform` / `appid` / `appsecret` / `enabled` | 决定该平台是「可自动发布」还是「人工发布（复制文案）」 |

### 业务线（biz_line）

| 值 | 名称 | 目标对象 | 卖点口径 |
| --- | --- | --- | --- |
| `project` | 甲方线 | 政企甲方 | 总代正品 + 大项目案例 + 全省交付服务 |
| `channel` | 渠道线 | 工程商 / 渠道商 | 不面对甲方不抢客户 + 2000 万现货 + 资质赋能投标 + 带证技术劳务输出 |
| `both` | 通用 | 两条线共用 | 素材库中通用素材对两条线都可见 |

### 素材公开级别（publicity）

| 值 | 名称 | 口径 | 是否进入 AI 生成上下文 |
| --- | --- | --- | --- |
| `public` | 可公开 | 可直接对外引用 | 是 |
| `masked` | 需脱敏 | 需人工改写（去客户名、去金额）后才可引用 | 是（**需人工确认改写**） |
| `internal` | 仅内部 | 不可外发 | **否**（`app/generator.py` 生成时过滤） |

### 选题规则

1. **主题分类**：`方案科普 / 案例复盘 / 工程商痛点 / 新品到货 / 招投标知识 / 公司动态 / 行业观点`。
2. **重复判断**：同主题 + 同角度的选题不重复建；已被生成的选题应置 `status=used`，避免重复出稿。
3. **内容频率**：每日 08:00 自动生成 1 个甲方线选题 + 1 个渠道线选题，每题 4 个平台版本，共 8 个版本（`app/generator.py`）。
4. **历史表现的使用**：`score` 为表现分，用于选题排序（`pick_topics` 按 `score desc` 取）；**当前后端不自动回填 score**，需人工维护（见《接口缺口清单》GAP-11）。

## 三、状态定义（与《分工》8.1 对齐）

### 3.1 内容状态 `contents.status`

| 状态 | 含义 | 页面表现 | 进入今日待办 |
| --- | --- | --- | --- |
| `draft` | 已生成或修改，尚未通过质检 | 标签「待审核」 | 是 |
| `approved` | 人工审核通过 | 标签「已通过」 | 是 |
| `rejected` | 人工驳回，**必须带理由** | 标签「已驳回」+ 顶部红条显示驳回理由 | 否 |
| `published` | 全部变体已回填链接（或公众号无需平台外链） | 标签「已发布」 | 否 |
| `archived` | 归档 | 标签「已归档」 | 否 |

> ⚠️ 《分工》8.1 的 `blocked`（命中红线禁止发布）**当前后端无对应字段**：变体只有 `compliance_ok` 布尔位，命中红线时置 `false`，由前端显式拦截。见《接口缺口清单》GAP-16。

### 3.2 变体人工确认状态 `content_variants.confirm_status`

| 状态 | 含义 | 页面表现 |
| --- | --- | --- |
| `none` | 未提交确认（含质检不达标被退回） | 标签「未提交确认」 |
| `pending` | AI 质检通过（合规 + 质量分 ≥ 70），等待人工确认 | 标签「待人工确认」，出现在工作台与待确认区 |
| `confirmed` | 人工已确认 | 标签「已确认」 |
| `rejected` | 人工已驳回 | 标签「已驳回」，需人工修订后重新提交 |

### 3.3 变体发布状态 `content_variants.publish_status`

| 状态 | 含义 | 页面表现 |
| --- | --- | --- |
| `none` | 未发布 | 标签「未发布」 |
| `queued` / `publishing` | 自动发布排队 / 进行中（仅在配置了平台官方凭据时出现） | 标签「排队中 / 发布中」 |
| `published` | 已回填有效链接 | 标签「已发布」+ 链接可点 |
| `failed` | 发布失败 | 标签「发布失败」+ 红色失败原因，可重试 |

### 3.4 线索状态 `leads.status`

`new` 新线索 → `contacted` 已联系 → `wechat_added` 已加微 → `opportunity` 商机 → `won` 已成交 / `lost` 已流失。

- 状态只能单向前进，`won` / `lost` 为终态；改回中间状态需在联系记录里写明原因。
- **没有联系记录的高意向线索不允许标为 `opportunity`**（运营判断，前端不强制阻断，但会在验收脚本中被判为问题）。

### 3.5 线索意向与身份

| 意向 `intent` | 判定口径 | 页面表现 |
| --- | --- | --- |
| `high` 高意向 | 询价、问联系方式、有项目要合作、问能否配合投标、问地州能否送货安装 | 左侧红色高亮 + 数据看板单列统计 |
| `mid` 中意向 | 问参数、型号、工期、品牌 | 橙色 |
| `low` 低意向 | 纯互动、点赞式留言 | 灰色 |
| `junk` 垃圾 | 广告、引流 | 浅灰，列入「异常状态」 |

| 身份 `identity` | 判定口径 |
| --- | --- |
| `contractor` 工程商 | 出现「我们有个项目 / 甲方要求 / 投标 / 安装队」等 |
| `owner` 甲方 | 出现「我们单位要建 / 采购」等 |
| `unknown` 未知 | 无法判定 |

### 3.6 线索去重规则（业务口径，后端尚未实现）

优先级：**联系方式优先 → 作者 + 平台其次 → 需求相似度兜底**；同一联系方式 30 天内不得重复新建线索。发现重复时人工合并：保留最早一条，把新线索的跟进记录并入旧线索，并在跟进记录里注明来源。当前系统只做**前端提示**（数据看板「线索质量提示」），不做自动合并（GAP-08）。

### 3.7 OCR 与外部推送状态（后端缺口）

《分工》8.1 定义的 `pending_review / confirmed`（OCR 任务）与 `pending / sent / failed / dead`（外部推送）**当前后端没有对应表与接口**：截图只落库不识别，企微推送只返回当次 `pushed` 布尔值。前端按「不可依赖」处理：截图提示手工录入，推送失败可手动重试（GAP-09、GAP-10）。

## 四、统计口径

| 指标 | 口径 | 取数接口 | 备注 |
| --- | --- | --- | --- |
| 已发布内容 | **有非空 `published_url` 的变体数** | `GET /dashboard/funnel` → `published` | 空链接不计数（硬门槛） |
| 总曝光 | `metrics.views` 求和 | 同上 → `views` | 只统计人工确认后录入的 |
| 评论 / 私信 | `interactions` 条数 | 同上 → `interactions` | 含 comment 与 dm |
| 线索总数 | `leads` 条数 | 同上 → `leads` | |
| 高意向 | `leads` 中 `intent=high` | 同上 → `high_intent` | |

- **数字与明细必须一致**：数据看板同时显示漏斗数字与「已发布明细」表，并做一致性核对；不一致时页面显示红色差异告警（口径问题见 GAP-14）。
- 趋势：后端无 `/dashboard/trend`，看板按「内容明细里的 `published_at`」在**前端本地聚合**最近 7 天，仅供趋势参考（标注在卡片下方）。

## 五、合规与拦截口径

1. **硬校验**（`app/generator.py:check_compliance` / `app/quality.py:score_variant`）：词库中 `forbidden` 与 `ad_law` 类型命中即 `compliance_ok=false`。
2. **打分**：`quality_score` 0-100，评分维度为选题相关性 30 / 信息增量 25 / 平台风格 15 / 口语化 15 / 无违规夸大 15；**< 60 不合格**，合规且 **≥ 70** 才进入 `confirm_status=pending`。
3. **拦截行为**（前端已实现，后端缺 `blocked` 状态）：
   - 命中红线的变体在待办、内容管理、工作台均显示红色拦截条，并给出命中词；
   - 待办页对命中红线的条目**不提供**「确认发布」入口，只允许复制文案供人工改写；
   - 修改并保存后，后端会重跑一次合规硬检，前端刷新显示新的合规结论。
4. `required` 类型规则（如「私信询价」）**当前只作提示词库，不参与拦截**（GAP-15）。
5. **禁用表达**：正文与话术不出现具体底价 / 成本价 / 出厂价；不出现「最便宜 / 全国第一 / 100% / 最低价」等广告法极限词；涉密案例不点名客户。

## 六、回复话术口径

- 渠道线：强调总代现货库存 + 不抢甲方客户 + 全省地州配送 + 资质赋能；
- 项目线：强调案例与全省服务；
- **任何回复不出现价格数字**，统一引导「私信询价」。

## 七、一期业务判定（本阶段我方结论）

| 编号 | 判定 | 依据 | 落地位置 |
| --- | --- | --- | --- |
| D-01 | 空发布链接不能计入发布量 | 《分工》十章硬门槛 | 前端回填前强制非空 + http(s) 校验；看板口径为「有链接的版本数」 |
| D-02 | 红线命中不能直接放行 | 《分工》十章硬门槛 | 前端红条 + 隐藏确认发布入口；建议后端补 `blocked` 状态（GAP-16） |
| D-03 | OCR 低置信度不能直接入库 | 《分工》十章硬门槛 | 一期无 OCR，数据只经人工录入，不存在自动入库路径（GAP-09） |
| D-04 | 同一联系方式 30 天内不得重复建线索 | 《分工》十章硬门槛 | 前端提示 + 人工合并；自动去重待后端实现（GAP-08） |
| D-05 | 驳回必须写理由，且理由要可见 | 《分工》4.2「用户能看懂每个版本为何通过或被拦截」 | 前端驳回理由必填 + 卡片顶部展示 `review_note` |
| D-06 | 一期以**人工发布**为验收口径，自动发布是可插拔增强 | 《分工》2.2、十一章风险表 | 「设置 · 平台发布模式」显示每个平台 auto/copy；顶栏显示当前模式摘要 |
| D-07 | 截图 OCR、竞品爬取、达人管理、多组织多品牌、平台全自动发布**不属于一期** | 《分工》2.2 | 「帮助」页明确列出，运营不会误认为一期必需 |
| D-08 | 驳回粒度：脚本要求「驳回 1 个版本」，后端只能整包驳回 | 《分工》十章 vs `app/api.py:review` | 前端按内容级展示；差异登记为 GAP-03，验收脚本第 3/4 步记为不通过 |

## 八、页面与状态对应关系

| 页面 | 展示的状态 | 允许的状态流转 |
| --- | --- | --- |
| 工作台 | 变体确认状态、发布状态、合规结论、质量分 | `pending → confirmed / rejected` |
| 今日待办 | 内容状态 + 变体发布状态 + 合规结论 | 未发布 → 已发布（回填链接） |
| 内容管理 | 内容状态、驳回理由、变体确认/发布状态、合规结论、质量分 | `draft → approved / rejected`；变体文案可改并重跑合规 |
| 素材库 | 公开级别、业务线、启用状态 | 新增 / 编辑 / 启停 / 删除（仅管理员） |
| 选题池 | 选题状态、表现分、业务线、主题 | `active ↔ used → archived` |
| 线索看板 | 意向、身份、负责人、线索状态、跟进记录 | 状态流转 + 指派 + 写跟进记录 + 重推企微 |
| 数据看板 | 漏斗五项 + 异常状态（红线 / 发布失败 / 待确认 / 未回填 / 未指派 / 无联系方式 / 重复联系方式） | 只读 + 指标录入 |
| 设置 | 角色可见范围、平台发布模式、合规红线、平台凭据、用户 | 凭据 / 红线 / 用户增删（仅管理员） |

## 九、边界

- 前端**不推断**后端状态：所有标签文案来自本说明与后端字段值映射（`web/js/core/format.js`），字段缺失一律显示 `-`。
- 后端**不承载展示文案**：本说明中的中文标签只在前端维护（`format.js`），后端返回原始状态值。
- 本说明不替代《接口缺口清单》：凡后端未实现的能力，一律在缺口清单登记，前端以占位 + 明确提示处理，不臆造已实现能力。
