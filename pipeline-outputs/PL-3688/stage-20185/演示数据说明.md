## 二、前置条件

1. `.env` 已配置（参考 `.env.example`）：

   ```ini
   DATABASE_URL=postgresql+psycopg://用户名:密码@主机:5432/库名
   MINIO_ENDPOINT=主机:9000      # 素材附件存储；不配则附件上传返回空 URL
   MINIO_ACCESS_KEY=...
   MINIO_SECRET_KEY=...
   MINIO_BUCKET=tuoke
   JWT_SECRET=任意随机串
   DEEPSEEK_KEY=...              # 内容生成与 AI 打标；不配则生成/打标失败
   WECOM_WEBHOOK=...             # 企微机器人；不配则高意向推送返回失败
   ```

2. 依赖已安装：`pip install -r requirements.txt`（含 `sqlalchemy`、`psycopg`、`fastapi`、`uvicorn`、`minio`、`bcrypt`、`python-jose`、`apscheduler`、`python-pptx` 等）。
3. 数据库已建好且为空：`createdb tuoke`，然后启动服务（首次启动会 `create_all` 建表并创建默认账号）。

## 五、演示数据 ↔ 九步验收对照

| 步骤 | 用到的演示数据 | 页面操作 | 期望看到 |
| --- | --- | --- | --- |
| 1 导入素材、建立选题 | 素材 3 条 + 选题 2 条 | 素材库「新增」/ 选题池「新增」 | 素材与选题可查询、可用于生成 |
| 2 触发内容生成 | 素材 + 选题 + 大模型 Key | 今日待办「生成明日内容包」 | 2 选题 × 4 平台 = 8 个版本 |
| 3 驳回 1 个版本并填理由 | 内容包 1（渠道线） | 内容管理 → 驳回 → 填理由 | 理由保留并展示；新版本自动生成（依赖 GAP-03） |
| 4 通过 7 个版本 | 8 个版本 | 内容管理 → 通过 | 今日待办 7 条；未通过的不出现 |
| 5 回填有效链接 | 待办中任意一条 | 今日待办 → 粘贴链接 → 确认回填 | 该版本变「已发布」，看板 +1；空链接被拒绝 |
| 6 上传数据截图并确认 OCR | 截图文件 | 今日待办 → 上传截图（数据截图） | OCR 未接入（GAP-09），提示手工录入；录入后曝光入库 |
| 7 上传评论截图并确认识别 | 评论截图 / 评论原文 | 线索看板 → 录入评论 → AI 打标 | 生成高意向线索（OCR 路径阻塞 GAP-09） |
| 8 指派销售 | 线索 1 条 | 线索看板 → 指派 → 改状态 → 写记录 → 推送企微 | 销售可见、状态与记录更新、企微可重试 |
| 9 核对看板与明细 | 全部 | 数据看板 | 漏斗数字 = 明细条数，页面显示一致性提示 |

## 六、复跑与清理

- **复跑**：九步脚本每次都从同一份种子数据出发。生产库演示前建议先备份：

  ```bash
  pg_dump "$DATABASE_URL" -Fc -f /tmp/tuoke-$(date +%F).dump
  ```

- **清理演示数据**（仅删演示行，保留真实数据）：

  ```sql
  DELETE FROM metrics       WHERE variant_id IN (SELECT id FROM content_variants WHERE published_url LIKE '%demo-acceptance%');
  DELETE FROM leads         WHERE contact_info = 'zhangsan88';
  DELETE FROM interactions  WHERE author_name = '老张做工程';
  DELETE FROM content_variants WHERE content_id IN (SELECT id FROM contents WHERE source = 'ai' AND scheduled_date = CURRENT_DATE);
  DELETE FROM contents      WHERE source = 'ai' AND scheduled_date = CURRENT_DATE;
  DELETE FROM topics        WHERE title LIKE '报告厅 LED 大屏怎么选：P1.5 和 P2.0 差在哪'
                            OR title LIKE '项目急要 LED 屏现货，厂家排产要 45 天怎么办';
  DELETE FROM materials     WHERE tags = '验收' OR title LIKE '%自由光科技公司简介%'
                            OR title LIKE '%京东方 LED 云南省总代%' OR title LIKE '%某中学报告厅%';
  ```

- **重新开始**：清空演示数据后重新执行方式 B 即可；方式 A 幂等，可重复执行。

## 七、本阶段验收所用环境（说明，非交付物）

本沙箱**没有 PostgreSQL 服务端二进制，也没有大模型 API Key**，真实 `app/` 无法启动。为完成前端走查与九步验收取证，本阶段在隔离目录内准备了两个**仅用于测试**的夹具（不进入交付物、不修改 `app/`）：

| 夹具 | 位置 | 作用 |
| --- | --- | --- |
| 后端桩 | `.pipeline/PL-3688/stage-20185/scratch/stub_app.py` | 照抄 `app/api.py` 的路由、字段与状态语义，内存数据代替数据库；同时提供 `POST /api/_reset` 让每次验收从同一起点开始 |
| 页面走查脚本 | `.pipeline/PL-3688/stage-20185/scratch/walkthrough.py` | Playwright 逐页截图 + 关键交互断言（登录 / 四态 / 回填校验 / 角色范围 / 断网错误态） |
| 交互走查脚本 | `.pipeline/PL-3688/stage-20185/scratch/ui_actions.py` | 弹窗表单校验、批量导入说明、按日期切换待办、评论录入打标、联系记录写回、驳回理由展示 |
| 九步执行器 | `.pipeline/PL-3688/stage-20185/scratch/nine_step_check.py` | 按第十节九步逐条执行并输出《九步验收脚本与结果.md》的原始记录 |

> ⚠️ 桩环境的结论**不能替代真实后端验收**：凡结论中标注「本环境无大模型 Key / 无 PostgreSQL」的步骤，必须在真实环境（PostgreSQL + Key + 企微机器人）复跑一次再对外宣布通过。
