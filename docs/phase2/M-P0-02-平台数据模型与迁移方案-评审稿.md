# M-P0-02 平台数据模型与迁移方案（评审稿）

> 版本：v0.1-评审稿　日期：2026-11-09　状态：待浆果评审签字
> 依据：D-02 拍板「`platforms` 数据表 + 保留旧 code 映射」；`app/models.py` 现有字段
> 原则：先加表、加可空外键、回填、双读、再收紧；任何一步都可回滚，不中断一期页面。

## 1. 目标

1. 平台从「代码里的枚举」变成「数据库里的配置」，支持停用、排序、自定义模板。
2. 新表 `platforms` 是唯一平台字典；旧 `platform` 字符串保留为迁移期兼容列。
3. 历史内容、账号、指标、OCR、互动、线索全部能按 code 映射到新平台；不丢数据。
4. 前端拿到稳定的 `platform_id` 与 `code`；展示以 `code` 为准，关联以 `platform_id` 为准。

## 2. 新表 `platforms`

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | 整数主键 | 是 | 自增 | 稳定主键 |
| `code` | varchar(32) | 是 | - | 唯一；小写字母/数字/下划线；创建后不可改 |
| `name` | varchar(50) | 是 | - | 中文展示名 |
| `icon` | varchar(200) | 否 | `''` | 图标 key 或相对路径 |
| `category` | varchar(20) | 是 | `other` | `video / note / article / marketplace / other` |
| `publish_mode` | varchar(20) | 是 | `copy` | `copy / official_api / browser / manual` |
| `home_url` | varchar(500) | 否 | `''` | 平台后台地址 |
| `default_time` | varchar(5) | 否 | `''` | `HH:mm`，内容默认发布时间 |
| `enabled` | 布尔 | 是 | `true` | 停用后不出现在新建/筛选，但历史仍显示 |
| `is_template` | 布尔 | 是 | `false` | 是否「可选模板」而非默认平台 |
| `sort` | 整数 | 是 | `100` | 越小越靠前 |
| `config` | JSON | 否 | `{}` | composer 字段模板、功能开关、平台特殊配置 |
| `created_at / updated_at / deleted_at / version` | 公共字段 | 是 | - | 与现有 `Record` 一致 |

约束与索引：

- `UNIQUE(code)`（逻辑删除后仍唯一；如需复用 code，先物理清理或加 `deleted_at` 部分唯一索引）。
- `INDEX(enabled, sort)`。
- `CHECK(category IN (...))`、`CHECK(publish_mode IN (...))`。

初始数据：

| code | name | category | publish_mode | enabled | is_template | sort |
|---|---|---|---|---|---|---|
| `douyin` | 抖音 | video | copy | true | false | 10 |
| `xhs` | 小红书 | note | copy | true | false | 20 |
| `gzh` | 公众号 | article | copy | true | false | 30 |
| `xianyu` | 闲鱼 | marketplace | copy | true | false | 40 |
| `shipinhao` | 视频号 | video | copy | false | true | 90 |
| `moments` | 朋友圈 | other | manual | false | true | 91 |

> 淘宝/快手/B 站不预置数据，由 R1「新增平台」按模板创建；预置会误导为已支持。

## 3. 关联表与外键

### 3.1 新增可空 `platform_id`

| 表 | 现值 | 新增 | 回填规则 |
|---|---|---|---|
| `content_variants` | `platform varchar(15)` | `platform_id int null` | 按 `platforms.code` 匹配 |
| `platform_accounts` | `platform varchar(15) unique` | `platform_id int null` | 按 code 匹配 |
| `ocr_tasks` | `platform varchar(15)` | `platform_id int null` | 按 code 匹配；空值保持空 |
| `interactions` | `platform varchar(15)` | `platform_id int null` | 按 code 匹配 |
| `leads` | 无 platform，经 interaction 关联 | 不新增 | 通过来源互动取平台 |

`content_variants` 唯一约束 `(content_id, platform, revision)` 在迁移期保留；新代码写 `platform_id` 时仍同步写 `platform`（code），保证旧查询可用。二期后段再评估改为 `(content_id, platform_id, revision)`。

### 3.2 账号表改造（与 M-P0-04 联动）

现 `platform_accounts.platform` 是 `UNIQUE`，只能一平台一账号。迁移分两步：

1. 新增 `account_key varchar(64)`（默认 `default`）、`platform_id`、`display_name`、`login_type`、`status`。
2. 删除 `UNIQUE(platform)`，改为 `UNIQUE(platform_id, account_key)`；旧的单账号记录回填 `account_key='default'`。
3. 详情见 `M-P0-04-多账号与会话模型-评审稿.md`。

## 4. 迁移步骤（Alembic）

| 步骤 | 操作 | 可回滚 | 验收 |
|---|---|---|---|
| 1 | 创建 `platforms` 表与索引 | 是（drop table） | 表存在，约束生效 |
| 2 | 写入 6 条初始平台（4 默认 + 2 模板） | 是（delete） | `SELECT code, enabled FROM platforms` 符合上表 |
| 3 | 各表新增可空 `platform_id` 与索引 | 是（drop column） | 旧代码不受影响 |
| 4 | 按 `platform` code 回填 `platform_id` | 是（置空） | 未匹配行数 = 0，或输出清单人工处理 |
| 5 | 账号表加 `account_key / login_type / status`，回填 `default` | 是 | 旧账号可登录/展示 |
| 6 | 后端读路径切到 `platforms`；写路径双写 `platform_id + platform` | 是（切回旧读） | 所有列表/详情平台名正确 |
| 7 | 前端切到默认四平台（M-P0-01） | 是（回滚前端） | 历史内容仍显示，xianyu 可用 |
| 8 | 观察一个迭代后，评估收紧 `platform_id NOT NULL` | 是 | 无空值、无未匹配 |

回填校验 SQL（PostgreSQL）：

```sql
-- 未匹配的历史 code
SELECT DISTINCT platform FROM content_variants
WHERE deleted_at IS NULL AND platform IS NOT NULL
  AND platform NOT IN (SELECT code FROM platforms WHERE deleted_at IS NULL);

-- 回填后仍为空的 platform_id
SELECT count(*) FROM content_variants
WHERE deleted_at IS NULL AND platform IS NOT NULL AND platform_id IS NULL;
```

SQLite 测试库用等价子查询；Alembic 迁移需同时兼容 PostgreSQL 与 SQLite（当前测试环境）。

## 5. 删除 / 停用规则

- **停用（enabled=false）**：不参与新建内容、默认筛选、账号新绑；历史内容与历史指标照常展示，标签置灰并标注「已停用」。
- **软删除（deleted_at）**：仅管理员可操作；有历史内容/账号/指标引用时禁止删除，只能停用；接口返回 409 并列出引用数量。
- **code 不可复用**：软删除后新建同 code 返回 409，避免历史数据串台。
- **模板平台**：`is_template=true` 的平台默认不启用；启用后按普通平台处理，但 `sort >= 90`。

## 6. 前端契约

`GET /platforms?enabled=true&include_templates=false` 返回：

```json
[
  {"id": 1, "code": "douyin", "name": "抖音", "icon": "douyin", "category": "video",
   "publish_mode": "copy", "home_url": "https://creator.douyin.com",
   "default_time": "18:00", "enabled": true, "is_template": false, "sort": 10,
   "config": {"composer": "douyin"}}
]
```

前端规则：

- `code` 用于显示与旧接口兼容；`id` 用于新接口关联。
- `config.composer` 指向 `web/js/core/platforms.js` 的通道 key；没有对应通道时按通用 `{title, body}` 渲染。
- 平台列表加载失败时，回退到 `PLATFORM_META` 默认四平台，并在页面顶部提示「平台配置加载失败，使用默认四平台」。
