# 二期接口缺口与待确认清单

> 版本：v1.0　日期：2026-11-09　整理：奇迹（前端）
> 核对基线：本地 `feat/frontend-jiangzhuofeng`，commit `10f88f1` + 本批未提交前端改动；核对方式为扫描 `app/api.py` 路由与 `app/models.py` / `app/schemas.py`。
> 用途：把前端验收中被后端卡住的点，转成可直接排期、可逐条验收的接口清单。**本文是缺口清单，不替代 `docs/API_CONTRACT.md`；字段为建议值，最终以浆果评审签字为准。**
> 说明：浆果的后端分支可能已有新进展；若某条已实现，请在该条“状态”回填 commit/PR，不重复开发。

## 0. 结论先行

- Phase 1 仍有 **7 组接口缺口 + 1 项用户资源缺口**；其中 3 组直接造成任务阻塞（批量审批、草稿箱、Gitee 镜像），4 组造成“前端就绪但不能联调”（筛选、版本切换、注册、限流）。
- 现有后端已具备单条审批、版本历史、线索/互动、选题、素材、OCR、outbox 等基础能力；缺的是**批量语义、内容写接口、平台配置化、多账号/沙盒、AI provider、评论/私信任务**。
- 已拍板的 D-01 ~ D-04 不再重复询问：默认四平台、`platforms` 表 + 旧码映射、关键节点人工确认、注册默认关闭 + 邀请码。
- 本清单中标注“需产品确认”的 3 项（草稿提交生成范围、批量驳回后是否异步重生成、批量上限/质量阈值）会影响契约，建议在 M-X-01 契约评审上一次性拍板。

## 1. P0：Phase 1 阻塞/待联调接口

### GAP-01 批量通过 / 批量驳回

| 项 | 内容 |
|---|---|
| 现状 | 只有 `POST /variants/{vid}/approve`、`POST /variants/{vid}/reject`；无批量端点 |
| 影响 | R4-03 只能逐条兼容（非原子）；R4-08 不能按“10 条中 1 条 blocked 整批不通过”验收 |
| 前端降级 | 先调 `POST /variants/batch-approve` / `batch-reject`；404/405 时逐条调用单条接口，UI 明示“可能部分写入，请核对列表” |
| 建议契约 | 见 [M-P0-05](M-P0-05-批量审核与版本对比接口-评审稿.md)：`variant_ids`、`expected_versions`、`note`、`dry_run`；成功 200 逐项结果；预检失败 409 `batch_precheck_failed` 且整批不写入；`admin/operator` 可调用，`sales` 403；写审计 |
| 验收 | ① 10 条中 1 条 blocked/已确认/非当前版本 → 409，0 条写入，逐项原因可见；② 10 条合格 → 全部通过；③ `dry_run=true` 不改变数据；④ sales 403；⑤ 审计可按 `batch_id` 查到操作者与结果 |
| 待确认 | 批量上限（建议首版 50）；质量分阈值（建议 ≥70）；驳回后新版本同步生成还是异步返回 `regenerate_task_id`（建议异步）；`dry_run` 是否首版提供（建议提供） |

### GAP-02 内容草稿的创建 / 编辑 / 提交

| 项 | 内容 |
|---|---|
| 现状 | 只有 `GET /contents`、`GET /contents/{cid}`、`POST /contents/{cid}/review`；无 `POST /contents`、`PUT /contents/{id}`、`POST /contents/{id}/submit` |
| 影响 | R4-07 草稿箱无法交付；为避免死入口，前端未放置“新建草稿”按钮 |
| 建议契约 | `POST /contents`：`biz_line/title/topic_id/scheduled_date/platforms[]` → 201 内容与草稿版本；`PUT /contents/{id}`：标题、排期、正文等 + `expected_version`；`POST /contents/{id}/submit` → 202 `{status, task_id}`，触发质检/审核；草稿 `status=draft`，未提交不进 `/todo/today` |
| 关键模型问题 | 现有 `contents` 只有标题/状态/排期，正文和平台在 `content_variants`。需浆果明确：创建草稿时是否按 `platforms[]` 一次生成 N 个草稿版本，还是先建内容壳、提交时再生成版本。**前端不预设，需在契约评审拍板。** |
| 验收 | 新建→编辑→保存→提交全流程；刷新后仍在；未提交不出现在待办；重复提交/版本冲突返回 409；operator 可写、sales 403 |
| 待确认 | 草稿提交后生成哪些平台的版本（用户手选 / 默认四平台）；草稿是否允许删除；正文编辑粒度是内容级还是版本级 |

### GAP-03 版本“设为当前”

| 项 | 内容 |
|---|---|
| 现状 | `GET /variants/{vid}/history` 可读 revision 链，但无切换当前版本的写接口 |
| 影响 | R4-04 只能做只读对比，“设为当前版本”按钮置灰 |
| 建议契约 | `POST /variants/{vid}/activate`，body `{expected_version}`；仅允许同一 `content_id + platform` 内的历史版本；切换后原当前版本 `is_current=false`，目标 `is_current=true`；返回更新后的版本；409 处理并发冲突；写审计 |
| 验收 | 切到旧 revision 后列表/对比/待办均以新当前版本为准；不能跨内容/平台切换；已删除版本不可激活；并发冲突可提示刷新 |
| 待确认 | 激活 blocked 版本是否允许（建议禁止，先解除 blocked）；激活后是否要重新质检（建议不重复质检，沿用历史结论并记录操作者） |

### GAP-04 内容列表的服务端筛选与分页

| 项 | 内容 |
|---|---|
| 现状 | `GET /contents` 仅接受 `status`、`scheduled`、`limit`（1–500）；前端为支持多维筛选一次拉 500 条本地过滤 |
| 影响 | R4-02、R4-05；真实数据量下首屏慢、统计口径可能与后端不一致 |
| 建议参数 | `platform`（code，兼容现前端）/ `platform_id`（R1 后）/ `status` / `variant_status` / `biz_line` / `keyword` / `scheduled_from` / `scheduled_to` / `quality_min` / `compliance`（`ok/fail`）/ `confirm_status` / `todo_only` / `page` / `page_size` |
| 响应兼容 | 现有前端按数组消费。建议首版保持数组 + `X-Total-Count` 响应头；或新增 `GET /contents/page` 返回 `{items,total,page,page_size}`，避免破坏一期页面。由浆果定，前端配合改服务层。 |
| 验收 | 8 个维度组合结果与本地筛选一致；分页不重不漏；空结果 200；非法参数 422；大数据量 P95 可接受 |
| 依赖 | 平台表/`platform_id` 落地（M-P0-02），否则平台筛选会二次返工 |

### GAP-05 选题来源字段与互动原帖链接

| 项 | 内容 |
|---|---|
| 现状 | `topics` 仅有 `biz_line/theme/title/angle/score/status/last_used_at`，无来源字段；`interactions` 无 `permalink`/原帖 URL |
| 影响 | R4-06 来源只能写入 `angle` 文本；线索详情能显示评论原文，但不能一键打开平台原帖；无法按来源做稳定统计/去重 |
| 建议契约 | `topics` 增加 `source_type`（`manual/lead/interaction`）、`source_id`、`source_url`（可空）；`interactions` 增加 `permalink`（可空）。`POST /topics` 接受来源字段并在 `GET /topics` 返回；按 `source_type+source_id` 可查询是否已转选题 |
| 迁移 | 现有 `angle` 中的“来源线索 #id｜平台｜访客”可保留；历史数据可按文本回填，或标记 `source_type=legacy_text`。不要求清洗旧文本。 |
| 验收 | 线索 #1 转选题后 `source_type=lead, source_id=1`；重复转选题可被后端识别（前端提示仍保留）；有 `permalink` 时详情可打开原帖，无则显示“暂无原帖链接” |
| 优先级 | P1（不阻塞 R4-06 当前可用版本，但影响可追溯性与 R7 线索质量） |

### GAP-06 注册配置与邀请码注册

| 项 | 内容 |
|---|---|
| 现状 | `POST /auth/login`、`GET /auth/me`、`POST /auth/password` 存在；`GET /auth/register/config`、`POST /auth/register` 均 404 |
| 影响 | R10-03 只能前端按“注册关闭”展示；无法验证开启注册、邀请码错误、待审批等真实分支 |
| 建议契约 | `GET /auth/register/config` → `{enabled, invite_required, default_role, approval_required, reason}`（GET 不必鉴权，但不得泄露邀请码）；`POST /auth/register` body `{username,password,invite_code}` → 201/202 `{status, user}`；关闭时 403；邀请码错误/过期 403/422；重复账号 409；弱密码 422；限流 429 |
| 数据 | 建议 `invite_codes(code, role, max_uses, used_count, expires_at, enabled, created_by)`；默认角色 `sales`；审批流可用 `users.status` 或 `enabled=false + pending`，需与现有 `enabled` 语义对齐 |
| 验收 | 关闭→无入口且直接调用被拒；开启+正确邀请码→待审批/可用符合契约；错误/过期/耗尽邀请码被拒；弱密码被拒；重复账号不泄露“账号已存在”以外的信息；管理员可停用 |
| 待确认 | 邀请码是否一次性、有效期、是否绑定角色；待审批用户能否登录（建议不能，返回统一提示） |

### GAP-07 登录限流与验证码挑战

| 项 | 内容 |
|---|---|
| 现状 | `POST /auth/login` 无失败计数、无 429、无验证码；30 并发错误密码全部 401 |
| 影响 | R10-02 只能用前端拦截桩演示；R10-04 限流项实测不通过 |
| 建议契约 | 连续失败 N 次（建议 5 次/账号或 IP/10 分钟）→ 429，body 含 `retry_after` 与可选 `challenge: {token, prompt, image_url}`；登录请求接受 `challenge_token/challenge_answer`；挑战一次性、有有效期；成功登录后清零计数；不得通过响应差异暴露账号是否存在 |
| 验收 | 连续错误触发 429；倒计时结束可重试；正确挑战答案可继续登录；错误答案被拒；30 并发下出现 429 且无 5xx；正常用户不受误伤（阈值/白名单策略需说明） |
| 待确认 | 限流维度（IP/账号/组合）、阈值与窗口、验证码形式（图形/算术/滑块）、是否仅生产开启（演示环境可配置） |

### 3.1 需产品拍板的 3 个契约问题

1. **草稿提交生成范围**：手工草稿提交后，是默认四平台各生成一个版本，还是让运营勾选平台？（影响 GAP-02 请求/响应）
2. **批量驳回后的新版本**：同步生成（请求可能很慢）还是异步返回 `regenerate_task_id`？（建议异步）
3. **批量审批门槛**：是否要求 `quality_score >= 70`、批量上限 50 还是 100？（建议 70 / 50，首版保守）

> 这 3 项不影响当前前端演示，但会影响浆果建表和接口形状，建议在下次 30 分钟契约评审上拍板。

## 5. 建议交付顺序

1. **平台表 / `platform_id`**（M-P0-02）：R4 平台筛选、R1、R6 都依赖，越晚做返工越大。
2. **批量审批/驳回**（GAP-01）：R4 核心验收，先于草稿箱。
3. **内容筛选 + 分页**（GAP-04）：可与批量并行，解决真实数据量性能。
4. **注册配置/注册 + 登录限流**（GAP-06/07）：R10 联调与安全验收。
5. **草稿箱三端点 + 版本切换**（GAP-02/03）：R4 剩余功能。
6. **选题来源/互动 permalink**（GAP-05）：可追溯性增强，可与 R7 一起做。
7. **R1/R2/R3/R6/R7/R9/R11 前置接口**：按二期排期分批评审，不在 Phase 1 强行插入。

## 6. 每个接口交付时的统一验收要求

- [ ] 已更新 `docs/API_CONTRACT.md` 与 OpenAPI，字段、状态、错误码与实现一致。
- [ ] 权限明确：admin / operator / sales 谁可读、谁可写；越权返回 403 且不泄露资源存在性。
- [ ] 错误码可执行：400/401/403/404/409/422/429/503 均有稳定 `code` 与中文文案。
- [ ] 写操作有 `expected_version` 或幂等键；冲突返回 409，不静默覆盖。
- [ ] 列表有分页/上限，不返回无界全量。
- [ ] 写操作有审计（actor、时间、对象、结果、IP/UA 视需要）。
- [ ] 至少覆盖正常、空、错误、无权限四态的自动化测试。
- [ ] 前端联调后回填本清单状态，不把“接口存在”当成“验收通过”。
