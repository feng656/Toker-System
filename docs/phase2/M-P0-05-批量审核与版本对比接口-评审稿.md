# M-P0-05 批量审核 / 版本对比接口（评审稿）

> 版本：v0.1-评审稿　日期：2026-11-09　状态：待浆果评审签字
> 依据：M-R4-03 / M-R4-04；现有 `POST /variants/{vid}/approve`、`/reject`、`GET /variants/{vid}/history`
> 原则：批量接口不绕过 blocked、未质检、非当前版本；全量预检失败则整批不写入；逐项结果可审计。

## 1. 批量通过 `POST /variants/batch-approve`

### 请求

```json
{
  "variant_ids": [101, 102, 103],
  "expected_versions": {"101": 3, "102": 1, "103": 5},
  "note": "11-09 上午批次",
  "dry_run": false
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `variant_ids` | int[] | 是 | 1–100 条；去重；顺序不影响结果 |
| `expected_versions` | object | 否 | key 为 variant_id 字符串，value 为读取时 `version`；缺失则不校验版本 |
| `note` | string | 否 | 审计备注，≤ 500 字 |
| `dry_run` | bool | 否 | true 只做预检，不写入；用于前端「预检」按钮 |

### 预检规则（全部通过才写入）

1. variant 存在、未删除、属于当前用户可见范围；
2. `is_current=true`；
3. `status=pending`（不是 draft / blocked / published）；
4. `confirm_status=pending`（未被其他人处理过）；
5. `compliance_ok=true` 且 `compliance_hits` 为空；
6. `quality_score >= 阈值`（默认 70，按内容配置）；
7. `expected_version` 与当前 `version` 一致；
8. 平台未停用（`platforms.enabled=true`）；
9. 同一内容同一平台只允许一个当前版本（数据库已保证）。

任一条失败：整批不写入，返回 409 与逐项失败原因。

### 响应（成功 200）

```json
{
  "batch_id": "ba_20261109_001",
  "requested": 3,
  "approved": 3,
  "failed": 0,
  "results": [
    {"variant_id": 101, "ok": true, "version": 4, "status": "pending", "confirm_status": "confirmed"},
    {"variant_id": 102, "ok": true, "version": 2, "status": "pending", "confirm_status": "confirmed"},
    {"variant_id": 103, "ok": true, "version": 6, "status": "pending", "confirm_status": "confirmed"}
  ]
}
```

### 响应（预检失败 409）

```json
{
  "code": "batch_precheck_failed",
  "detail": "3 条中有 1 条未通过预检，整批未写入",
  "batch_id": "ba_20261109_002",
  "requested": 3,
  "approved": 0,
  "failed": 1,
  "results": [
    {"variant_id": 101, "ok": true, "code": "ok", "message": "可审批"},
    {"variant_id": 102, "ok": false, "code": "blocked", "message": "命中合规红线：绝对化用语", "compliance_hits": "最,第一"},
    {"variant_id": 103, "ok": true, "code": "ok", "message": "可审批"}
  ]
}
```

> `results` 中 `ok=true` 只表示「预检通过」，不是「已写入」。前端必须看顶层 `approved` 与 HTTP 状态。

### 权限

- `admin / operator` 可批量通过；`sales` 403。
- 操作写入审计：`batch_id / actor / variant_ids / result / note / ip / ua`。
- 单条审批仍保留 `POST /variants/{vid}/approve`，供详情页使用。

## 2. 批量驳回 `POST /variants/batch-reject`

### 请求

```json
{
  "variant_ids": [101, 102],
  "reason": "封面文案与业务线不符，请按驳回理由重生成",
  "expected_versions": {"101": 3, "102": 1},
  "dry_run": false
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `variant_ids` | int[] | 是 | 1–100 条 |
| `reason` | string | 是 | 1–2000 字；不能全空白 |
| `expected_versions` | object | 否 | 同上 |
| `dry_run` | bool | 否 | 预检 |

### 语义

- 预检规则同批量通过，但要求 `status=pending` 且 `confirm_status=pending`；
- 每条驳回后按现有 `reject_variant` 逻辑生成新版本（若生成失败，旧版本保留理由，返回 `new_variant=null` 与 `retry_url`）；
- 整批预检失败不写入任何一条；
- 生成新版本是逐条独立事务还是整批事务：**建议整批事务只覆盖「状态变更」，生成新版本可异步**，避免一次批量触发 100 次 AI 调用。首版建议同步写入驳回状态，新版本由任务队列异步生成，响应返回 `regenerate_task_id`。

### 响应

```json
{
  "batch_id": "br_20261109_001",
  "requested": 2,
  "rejected": 2,
  "failed": 0,
  "regenerate_task_id": "task_123",
  "results": [
    {"variant_id": 101, "ok": true, "new_variant_id": 201, "revision": 4},
    {"variant_id": 102, "ok": true, "new_variant_id": null, "retry_url": "/api/v1/variants/102/regenerate"}
  ]
}
```

## 3. 版本对比 `GET /variants/{vid}/history`

现有接口已返回同一 `content_id + platform` 的 revision 链。补充字段与排序：

| 字段 | 说明 |
|---|---|
| `id` | 版本 ID |
| `revision` | 版本号，递增 |
| `is_current` | 是否当前版本 |
| `status` | `draft / blocked / pending / published` |
| `confirm_status` | `none / pending / confirmed / rejected` |
| `publish_status` | `none / publishing / filled / submitted / published / failed` |
| `body / cover_text / hashtags` | 对比正文 |
| `quality_score / quality_note` | 质检分与评语 |
| `compliance_ok / compliance_hits` | 合规结论 |
| `rejection_reason` | 驳回理由（若有） |
| `parent_id` | 父版本 ID |
| `created_at / updated_at / version` | 时间与乐观锁 |

排序：`revision ASC`；前端默认选中「当前版本」与「上一个版本」。若只有一条，显示「暂无历史版本」。

补充要求：

- 历史版本必须包含已软删除版本吗？**不包含**；删除版本不参与对比。
- 对比接口不返回其他内容/平台的版本，前端无需二次过滤。
- 前端本地 diff，不上传正文到第三方服务。

## 4. 错误码

| HTTP | code | 文案 | 前端动作 |
|---|---|---|---|
| 400 | `batch_empty` | 未选择任何版本 | 提示选择 |
| 403 | `forbidden` | 无审批权限 | 隐藏按钮 |
| 404 | `variant_not_found` | 版本不存在或已删除 | 刷新列表 |
| 409 | `batch_precheck_failed` | 存在未通过预检的版本，整批未写入 | 展示逐项原因 |
| 409 | `version_conflict` | 数据已被他人更新 | 刷新后重试 |
| 422 | `invalid_reason` | 驳回理由不能为空 | 聚焦理由输入 |
| 429 | `rate_limited` | 操作过于频繁 | 倒计时 |
| 503 | `generator_unavailable` | 生成服务暂不可用 | 保留驳回状态，稍后重试 |

## 5. 前端兼容策略（当前后端未上线批量接口）

- 前端先调用批量接口；若返回 `404/405`，切换「兼容模式」逐条调用现有 `/variants/{vid}/approve`、`/reject`。
- 兼容模式必须在 UI 明示：「当前为逐条兼容模式，后端批量接口未就绪」。
- 兼容模式仍做同样的全量预检；任一条失败则整批不提交（先预检，后逐条写入）。
- 逐条写入若中途失败，展示已成功/失败清单，不谎报整批成功。
- 批量接口上线后删除兼容分支，只保留批量调用。
