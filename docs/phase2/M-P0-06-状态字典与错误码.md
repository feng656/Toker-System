## 2. 内容与审核

### 2.1 内容包 `contents.status`

| 值 | 文案 | 说明 |
|---|---|---|
| `draft` | 待审核 | 含未审核/待处理版本 |
| `approved` | 已通过 | 至少一个版本可发布 |
| `rejected` | 已驳回 | 有驳回理由 |
| `published` | 已发布 | 至少一个版本已回填链接 |
| `archived` | 已归档 | 只读 |

### 2.2 内容版本 `content_variants.status`

| 值 | 文案 | 可执行操作 | 禁止操作 |
|---|---|---|---|
| `draft` | 草稿 / 待质检 | 编辑、质检 | 审批、发布 |
| `blocked` | 已拦截 | 修改文案、重新质检 | **审批、发布** |
| `pending` | 待人工确认 | 通过、驳回、查看历史 | 直接发布（需先确认） |
| `published` | 已发布 | 查看、回填链接 | 编辑正文、重新质检 |

### 2.3 人工确认 `confirm_status`

| 值 | 文案 | 说明 |
|---|---|---|
| `none` | 未提交确认 | 尚未进入人审 |
| `pending` | 待人工确认 | 可审批 |
| `confirmed` | 已确认 | 可进待办/发布 |
| `rejected` | 已驳回 | 看驳回理由；可重生成 |

### 2.4 发布进度 `publish_status`

| 值 | 文案 | 说明 |
|---|---|---|
| `none` | 未发布 | 初始 |
| `publishing` | 发布中 | 自动发布进行中 |
| `filled` | 已填充 | 浏览器沙盒已填表，待人工确认 |
| `submitted` | 已提交 | 平台已接收，待回填链接 |
| `published` | 已发布 | 有真实公开链接 |
| `failed` | 发布失败 | 看 `publish_error`，可重试 |

> `status` 是内容审核状态，`publish_status` 是发布操作进度，二者不能混用。

## 7. HTTP 错误码

| HTTP | code（建议） | 前端主文案 | 可执行下一步 |
|---|---|---|---|
| `0` | `network_error` | 网络异常，连不上后端服务 | 检查服务/网络，重试 |
| `400` | `bad_request` | 请求参数有误 | 修正后重试 |
| `401` | `unauthorized` | 登录已失效，请重新登录 | 回登录页 |
| `403` | `forbidden` | 当前角色没有该操作权限 | 联系管理员/切换账号 |
| `404` | `not_found` | 数据不存在或已删除 | 刷新列表 |
| `409` | `conflict` | 数据已被他人更新或状态不允许此操作 | 刷新后重试；不要自动覆盖 |
| `409` | `batch_precheck_failed` | 存在未通过预检的版本，整批未写入 | 查看逐项原因 |
| `409` | `account_not_ready` | 平台账号未登录或已过期 | 重新扫码 |
| `422` | `validation_error` | 提交内容有误 | 按字段提示修改 |
| `429` | `rate_limited` | 操作过于频繁，请稍后重试 | 按 `retry_after` 倒计时；完成挑战 |
| `500` | `server_error` | 服务内部错误 | 稍后重试；记录 request_id |
| `503` | `service_unavailable` | 依赖服务暂不可用 | 稍后重试；不要重复提交 |

### 7.1 429 返回约定

```json
{
  "code": "rate_limited",
  "detail": "登录尝试过于频繁",
  "retry_after": 30,
  "challenge": {
    "required": true,
    "token": "ch_xxx",
    "type": "image",
    "prompt": "请输入图中字符",
    "image_url": "/api/v1/auth/challenge/ch_xxx.png",
    "expires_at": "2026-11-09T12:00:30Z"
  }
}
```

- `Retry-After` 响应头优先于 body `retry_after`。
- 无挑战时只显示倒计时；有挑战时展示挑战并在登录请求中带 `challenge_token / challenge_answer`。
- 不泄露账号是否存在：登录失败统一「账号或密码错误」。

### 7.2 409 返回约定

```json
{
  "code": "version_conflict",
  "detail": "数据已被他人更新，请刷新后重试",
  "current_version": 5,
  "expected_version": 4
}
```

前端展示 `detail`，提供「刷新」按钮；不自动重放写请求。

### 7.3 503 返回约定

```json
{"code": "service_unavailable", "detail": "生成服务暂不可用", "retry_after": 60}
```

前端提示稍后重试；保留用户已填内容，不清空表单。

## 8. 实现约束

1. 页面只引用 `status.js` 的 `*_STATUS` / `*_LABEL` / `httpErrorInfo()`，不写死中文。
2. 未知状态回退显示原始 code，并附「未知状态」提示；不静默当作成功。
3. 状态颜色统一：成功绿、进行中蓝、等待人工橙、失败红、停用灰。
4. 所有「下一步」必须可点击或明确指向页面；不能只写「请联系管理员」而没有入口。
5. 后端新增状态必须先更新本文件与 `status.js`，再改页面。
