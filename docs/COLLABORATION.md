# 双人协作规则与本批分工

- main只保存双方审核、联调通过的代码。不得直接push main、强推main或自动合并。
- 每批从最新基线建立功能分支，commit → push → Pull Request → 互审 → 联调 → 维护者合并 → 双方pull。
- 浆果范围：app、数据库迁移、后端scripts/tests、部署、接口/测试文档。
- 另一位范围：web与前端交互、业务素材口径、运营试跑和最终验收。此次web/index.html与远端初始源码逐字一致。
- 当前分支feat/jiangguo-backend-closure基于已有协作基线3da28df继续，不覆盖或重写该历史。
- 修改接口含状态/兼容差异必须在PR和docs/API_CONTRACT.md说明。任何冲突先确认，不覆盖另一方在途内容。
- PR未完成前端联调和真实外部服务验收时保持Draft，不点合并、不宣称完成上线。
